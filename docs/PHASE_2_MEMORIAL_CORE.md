# 阶段 2：纪念册核心

阶段 2 把基础平台扩展为可投稿、可审核、可浏览的最小纪念册，并逐步接入 AList 媒体存储。媒体原文件仍只写入 AList 所限定的 `3048` 目录，应用数据库只保存业务元数据和对象路径。

## 当前可验收切片

第一切片已实现纯文字帖子的完整状态机：

1. 成员创建草稿，或直接提交为待审核内容。
2. 草稿仅作者可见、可编辑；提交后不可再按草稿覆盖。
3. 管理员可以批准发布或隐藏待审核内容。
4. 普通首页只返回已发布且对成员可见的内容。
5. 作者可以查看自己的全部状态；管理员可以查看待审核队列。
6. 删除采用软删除，保留审计与后续媒体清理依据。

对应接口：

- `GET /api/posts?scope=feed|mine|pending`
- `POST /api/posts`
- `GET|PATCH|DELETE /api/posts/{id}`
- `POST /api/posts/{id}/submit`
- `POST /api/admin/posts/{id}/moderate`

## 内容状态机

```text
draft ──提交──> pending ──通过──> published
                     └──隐藏──> hidden

draft / pending / published / hidden ──删除──> deleted
```

只有作者可以编辑草稿、提交或删除自己的内容；管理员可以执行审核操作。待审核、隐藏和已删除内容不会进入普通成员的首页内容流。

## 数据模型

迁移 `0002_memorial_content.sql` 新增帖子、媒体、帖子媒体关联、标签、评论、回应、留言和上传任务表，并为用户加入默认 20 GiB 媒体配额。媒体记录具有独立处理状态，便于后续区分上传中、可用、失败和远端不可用。

## 媒体上传切片

媒体上传切片已经完成：

1. 浏览器使用原始请求体上传，Go 服务逐块转发给 AList，不创建完整本地临时文件。
2. 每次上传使用客户端请求 ID；重复的成功请求返回同一媒体记录，不会再次写入远端。
3. 写入前在 SQLite 中预留用户额度，并把并发中的上传一起计入额度。
4. AList 写入完成后重新读取远端元数据，只有大小一致才创建 `ready` 媒体记录。
   夸克驱动可能先确认写入、稍后才刷新元数据，因此校验采用有上限的退避重试，而不是第一次查不到就误判失败。
5. 写入或验证失败时记录失败码并清理可能存在的远端残留；清理失败会进入 `cleanup_required` 状态。
6. 投稿只允许绑定当前作者已经上传完成的媒体；已绑定媒体不能绕过帖子直接删除。
7. 发布器展示待上传、上传进度、失败重试和用户媒体空间占用，支持图片或视频形式的无文字投稿。
8. 媒体读取要求登录并再次检查作者、管理员或已发布内容权限；缓存未命中的视频 Range 请求透传给 AList，图片采用懒加载。
9. 内容流在远端读取失败时显示占位和“重新加载”，不会用破损媒体冒充正常内容。
10. 支持 JPEG、PNG 和 GIF 的尺寸读取与 960px JPEG 预览生成；超过 2400 万像素时只记录尺寸，不在小内存服务器中完整解码。
11. 浏览器在上传前读取视频宽高和时长，后端执行范围校验后保存；视频原文件继续通过 Range 代理播放。
12. 开放照片墙和时间线：照片墙使用懒加载预览，时间线优先按内容日期、其次按发布日期分组。
13. 个人头像复用受配额约束的图片上传链路，头像媒体对登录成员可见；上传前可调整缩放、横纵位置和 256/512/1024 输出尺寸，大于 2 MiB 的原图在浏览器端压缩为 JPEG；更换头像后安全清理未被帖子引用的旧媒体。
14. 帖子详情集中展示原始媒体、点赞状态和评论；普通成员只能评论已发布的成员内容，评论作者和管理员可以删除评论。
15. AList 预览对象暂不可读时自动回退原图，避免头像和内容卡片显示为破损图片。
16. 应用默认使用 2 GiB 本地磁盘缓存。新上传对象直接预热缓存，远端对象只有完整读取后才进入缓存，未完整传输的临时对象会丢弃；缓存命中及视频 Range 命中不再访问 AList，并按最近访问时间淘汰旧对象。

生产环境应为应用使用独立 AList 用户，并把该用户的基础路径限制在 `3048`。如果 AList 中该用户看到的 `/` 已经是 `3048`，则配置 `ALIST_ROOT=/`；不要再次填写 `/3048`。

真实 AList 验证使用 189,164 字节 PNG 完成了流式写入、远端大小校验和远端删除，测试对象已清理。
