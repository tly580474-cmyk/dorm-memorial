## 已实现行为与边界

- 使用 ffprobe 读取实际容器、编码、像素格式、profile/level、帧率、尺寸、码率及音轨；兼容性判定保守，探测失败时转码。检测通过且 Fast Start 的原文件直接作为播放版引用，不复制、不再次上传；仅缺 Fast Start 时重封装。
- 原文件始终保留。普通内容接口不带参数仍读取原文件；播放器使用 `variant=watch`，优先选择已登记的播放版，否则暂用历史原文件。原文件被复用时删除路径去重，配额仍按原文件计算。
- `watch` 响应要求浏览器重新验证，ETag 包含最终选择的版本，避免历史原文件后来补出播放版却仍命中旧缓存。响应提供 `X-Media-Variant`；仅真正等待生成的错误提供 `X-Media-State: preparing`。
- 新增数据库迁移 `0014_media_processing_checkpoints.sql` 保存阶段结果。重启恢复验证本地原文件哈希、播放文件大小/Fast Start、封面格式及已保存远端对象；有效结果跳过重复处理。新上传不立即重复计算整文件哈希。
- 上传暂时性错误最多尝试三次（立即、等待 1 秒、再等待 3 秒），每次重新打开本地文件。重试过程中保留已完成结果；永久错误或重试耗尽后失败并尝试清理。本轮没有增加人工续传接口、无限重试或无限期保留暂存。
- 编码器枚举缓存十分钟；编码仍有 GPU→CPU 回退。编码与 Fast Start 保持分阶段，封装独立尝试两次，不因封装失败重新编码。历史视频补处理共用同一准备策略。
- 视频帧率不高于 30fps，低帧率保留；码率保持 700～4000 kbps 的边界，取消此前 1.5 倍放大。兼容性转码仍不保证比原文件更小。
- 播放读取不再自动启动额外整文件预热。上传写入缓存、完整读取形成缓存、Range 缓存读取及 LRU 淘汰保留。
- 前端只在播放错误后读取同源视频接口的一字节范围进行诊断，并立即取消响应体；外链不诊断。自动重试有上限，支持手动重试及尝试原文件。
- 上传处理轮询由 1.5 秒退避至 5 秒；使用 `include_usage=0` 省去反复汇总配额，完成后获取含媒体记录和用量的最终响应。

## 暂缓事项

- 原文件上传与编码并行：先测各阶段耗时、磁盘占用和远端吞吐，确认瓶颈再调整。
- 减少 AList 强制刷新：先在实际存储驱动上验证一致性，保留现有远端校验。
- 合并任务状态表：优先集中状态更新，不为减少表数量而进行额外迁移。
- 分块缓存、多清晰度、分布式任务队列：当前没有容量证据支持引入。
