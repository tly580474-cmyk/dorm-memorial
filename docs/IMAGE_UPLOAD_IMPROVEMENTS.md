# 图片上传改进清单

范围：图片选择、上传、远端验证、缩略图与展示版、失败重试和清理。以下清单已实现并通过回归验证；尚未部署到运行中的服务。保留原文件，不自动删除已经上传成功但尚未关联内容的素材。

## 处理全流程

1. 前端获取服务端限制，选择图片并检查大小、格式；头像先裁剪，再检查输出文件。
2. 携带上传ID发起请求；服务端检查身份、配额和任务状态，协调同ID请求及失败重试。
3. 暂存文件，核对精确长度、真实格式与 MIME，检查尺寸和 GIF 帧预算，完整解码；规范文件后缀，保留原始字节。
4. 写入远端原图，绕过本地缓存读取远端对象，检查长度和 SHA256。
5. 尝试生成缩略图，应用 EXIF 方向和缩放后保存；缩略图失败不丢弃已验证的原图，并清理未登记衍生文件。
6. 登记可用媒体并返回成功；前端此时才结束处理状态，发布内容时关联媒体。
7. 浏览时检查读取权限，按需生成展示版并归档；GIF、无法渲染的旧图或不可读展示版回退原图，浏览器也提供有限重试与降级。
8. 失败时记录清理状态、回收配额并清理远端残留；服务启动时继续恢复遗留任务。删除与展示版归档按媒体ID协调。

## 实施清单

| 优先级 | 问题 | 改进与验收标准 |
| --- | --- | --- |
| P1 | 各入口大小限制不同 | 通过登录后的 `/api/media/limits` 获取实际图片大小、格式限制；帖子、正文插图、留言、消息共用校验 |
| P1 | 只信任 MIME，损坏文件也能入库 | 在写远端前暂存并检查实际图片；伪造、截断与不支持格式不能成为 `ready` |
| P1 | 远端只有大小校验 | 图片绕过本地缓存读回远端对象，比对长度及 SHA256；同长度损坏也必须失败并清理 |
| P1 | 重试生成新上传ID | 同一队列项保持上传ID；后端安全复用已完成结果、恢复可重试失败任务，拒绝请求ID混用 |
| P1 | 异常退出残留任务占配额 | 启动维护回收同步上传遗留任务；排除视频后台任务，不删除已完成素材 |
| P1 | 缩略图部分写入残留 | 原图成功时只清理未登记的失败缩略图；删除失败持久记录 `preview_cleanup_required`，启动维护继续清理，保留 ready 原图 |
| P2 | 展示版归档与删除竞态 | 按媒体ID协调删除和归档登记；展示版写入或数据库登记失败时，使用独立上下文清理未登记衍生文件，保护原图 |
| P1 | 展示版失败导致无法看图 | 已保存的展示版不可读时回退原图；浏览器在展示版重试失败后自动降级，并避免无限重试 |
| P2 | WebP不能生成衍生图 | 增加 WebP 解码；实际上传格式限制为 JPEG、PNG、GIF、WebP |
| P2 | 照片旋转与缩放质量 | 衍生图应用 EXIF 方向、改进缩放；原文件字节保持不变 |
| P2 | GIF查看器丢失动画 | GIF查看使用原图，忽略旧静态展示版；列表缩略图仍可静态显示 |
| P2 | 上传100%被误认为处理完成 | 文件发送结束后明确显示服务器仍在保存和校验，直到成功响应才可关联发布 |

## 兼容与部署边界

- 图片继续使用同步上传接口，不引入视频转码队列。
- 网络中断可以重新上传；不提供分片断点续传。
- 原图、缩略图、展示版继续通过带权限检查的应用接口读取。
- 成功但尚未关联内容的文件可能属于草稿，不能自动当作垃圾删除。
- 真实远端校验会增加一次原图读取，耗时与流量取决于 AList 和底层网盘。
- 新图片最多 2400 万像素；GIF 的累计帧像素也最多 2400 万、最多 256 帧。先检查尺寸与帧结构，再完整解码验证；全局同一时间仅执行一次图片解码，避免并发放大内存占用。
- 新衍生图使用 Catmull–Rom 缩放，JPEG 应用 EXIF 1–8 方向。原文件不重编码、不移除 EXIF；已经归档的历史 JPEG 衍生图不会自动批量重算。
- 旧大图和不支持渲染的旧格式尽量回退原文件；最终能否显示仍取决于浏览器是否支持该格式。新上传不接受 HEIC、AVIF、SVG 等未支持格式。
- 旧图元数据超过展示版读取上限（8 MiB）时也直接回退原图，不反复等待无法完成的衍生图生成。
- 图片、头像和同步音频重试保持请求ID；视频每次重试继续使用新ID，避免复用已失败的后台处理任务。
- 上传暂存使用系统临时目录中的 `dorm-image-upload-*.part`，正常成功、失败均删除。进程被强制终止时可能残留临时文件，本轮没有增加跨进程自动删除，以免清理仍在使用的文件。
- 新增迁移 `0015_upload_job_metadata.sql`，只给上传任务增加预览路径和请求指纹字段。异常退出后恢复的是任务状态与远端清理，不是从中断字节继续上传。
- 测试和前端构建应使用隔离输出目录，不覆盖正在运行服务的 `web/dist`。上线前需结束上传任务、备份数据库，并一起更新前后端。
