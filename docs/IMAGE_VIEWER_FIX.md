# 图片查看器加载与重影修复（2026-08-30）

用户反馈：`IMG_20260821_102738.jpg` 首次加载等待较久，加载后出现不同尺寸图片重叠。

## 原因与调整

- 预览层始终存在，且带有半透明及滤镜；在大窗口下，960×720 的预览图与更大的清晰图形成重影。现在加载完成即移除占位层，不再依赖透明度叠放。原图下载期间暂用已加载的清晰图，原图就绪后只保留原图。
- 切图、关闭及异步加载事件原先没有完整隔离。现在按图片和打开状态重置，忽略旧图片迟到的事件，并在成功或关闭时取消重试。
- 原先首次请求缺失的 `display` 版本会返回 503，后台生成、上传到网盘、登记数据库后，浏览器才通过退避重试取到图片。现在同一图片的请求共享生成结果，JPEG 生成后直接返回，网盘保存与登记在后台继续。已登记的版本仍走原有文件缓存和读取路径。
- 同时最多保留四项生成/保存任务，最多并行解码两张图片，任务两分钟超时，防止慢网盘造成无限内存积累。只有保存成功才登记版本；保存期间被删除的照片不会被恢复，并清理生成的孤立文件。
- 解码前检查像素上限，通过保留文件头避免重复打开原文件。邻图预取使用与正式查看一致的 URL，并设为低优先级，避免 `prefetch=1` 造成浏览器缓存无法直接复用。

原图不变；仍提供最长边 2048 像素的清晰版，原图只在用户点击后加载。远端原文件未缓存、并发任务已满或网络较慢时仍可能等待，本次不承诺所有图片瞬时加载。

## 验证与运行更新

- 五项图片查看器回归覆盖占位层移除、清晰版到原图切换、父组件切图、取消重试及迟到事件；修改前的四项核心回归均失败，修改后通过。
- 后端测试阻塞网盘保存，确认清晰图仍可立即返回、重复请求只解码一次；另验证保存失败不影响已返回的图片，以及保存中删除不恢复照片。
- 前端全部 33 项测试、类型检查及构建通过；`go test ./internal/... ./cmd/...`、`go vet ./internal/... ./cmd/...` 和媒体/HTTP/缓存三个包的 race 检查通过。
- 实际浏览器在 1965×1200 下复现预览图 960×720、清晰图 1344×1008 的叠加；更新后确认只剩一张图片。已验证 2048×1536 清晰版、4096×3072 原图及来回切图，均无重影。
- 反馈图片再次打开约 1.6 秒进入已加载状态，此时已有清晰版和缓存；该数值不是首次生成的冷启动性能对比。
- 确认无正在上传的任务后，备份至 `backups/before-image-viewer-fix-20260830-1314.db`，于 13:15 更新前后端并重启应用，健康检查通过。旧前端资源保留以兼容尚未刷新的页面，AList/Caddy 未重启，本轮没有数据库迁移。
